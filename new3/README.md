# Сайт Гимназии № 4

Статический многостраничный сайт образовательной организации. Чистый HTML, CSS и небольшой JavaScript: **для отображения не нужны Python, Node.js, npm, сборщик или база данных**. Сайт лежит в корне репозитория; `index.html` — точка входа.

> Это демонстрационная версия. Наименование, адрес, контакты, руководство и условия приёма в 1 класс взяты с действующего сайта gym4.net (см. [docs/GYM4_DATA.md](docs/GYM4_DATA.md)) и ждут подтверждения администрацией. Остальные сведения оставлены заглушками вида `[внести данные]` и не выдуманы.

## Структура

```
index.html            Главная
sveden.html           Сведения об образовательной организации
parents.html          Родителям
students.html         Обучающимся
news.html             Новости и объявления
priem.html            Приём в гимназию
contacts.html         Контакты
404.html              Страница ошибки
robots.txt            Правила для поисковых роботов
.nojekyll             Отключает обработку Jekyll на GitHub Pages
assets/css/style.css  Единый стиль (цвета и размеры — переменные в :root)
assets/js/app.js      Меню и версия для слабовидящих (без него сайт читаем)
assets/img/           Значок сайта; сюда же кладутся изображения
tools/check_site.py   Проверка ссылок, якорей, заголовков (только stdlib Python)
docs/                 Руководство администратора, чек-лист данных, отчёт об аудите
.github/workflows/    Проверка и публикация на GitHub Pages
```

## Локальный просмотр

Откройте `index.html` в браузере двойным щелчком. Для проверки через HTTP-сервер (любой, например встроенный в Python):

```bash
python3 -m http.server 8000     # затем http://localhost:8000
```

## Проверка перед публикацией

```bash
python3 tools/check_site.py     # ссылки, якоря, один h1, lang, внешние ресурсы, эмодзи
node --check assets/js/app.js   # синтаксис скрипта (необязательно)
```

Те же проверки выполняет GitHub Actions при каждом push и pull request.

## Публикация демонстрации на GitHub Pages

1. Поместите содержимое проекта в **корень** репозитория, ветка `main`.
2. В **Settings → Pages** выберите **Source: GitHub Actions** (не «Deploy from a branch»).
3. Выполните push в `main`. Workflow `.github/workflows/pages.yml` проверит сайт и опубликует каталог `_site`, в который копируются только `*.html`, `assets/`, `robots.txt`, `.nojekyll`. Каталоги `docs/` и `tools/` не публикуются.
4. Адрес появится в сводке запуска: `https://<аккаунт>.github.io/<репозиторий>/`. Все ссылки на сайте относительные, поэтому работа из подкаталога репозитория не нарушается.

Ограничение: страница `404.html` использует относительные пути и корректно отображается на адресах первого уровня (`/<репозиторий>/несуществующая`). На собственном домене в корне это не имеет значения.

## Установка на сервер школы

Скопируйте файлы (кроме `docs/`, `tools/`, `.github/`, при желании) в каталог веб-сервера. Подробности, примеры конфигурации Nginx/Apache, HTTPS, заголовки безопасности и резервное копирование — в [docs/ADMIN_GUIDE.md](docs/ADMIN_GUIDE.md).

## Передача администратору

1. Передайте репозиторий или ZIP-архив, а также [docs/ADMIN_GUIDE.md](docs/ADMIN_GUIDE.md) и [docs/CONTENT_CHECKLIST.md](docs/CONTENT_CHECKLIST.md).
2. Назначьте ответственных за содержание разделов (см. чек-лист).
3. Найдите все заглушки командой `grep -rn "class=\"ph\"" *.html` и замените их проверенными данными.
4. Удалите полосу «Демонстрационная версия» (элемент `demo-strip` в каждой странице) и пометки «Раздел не заполнен» только после внесения данных.
5. Прогоните `tools/check_site.py`, проверьте страницы на телефоне и с клавиатуры.

## Что сайт не делает

- Не отправляет и не сохраняет данные посетителей: формы обратной связи нет намеренно (см. `contacts.html` и ADMIN_GUIDE).
- Не использует cookie, счётчики, внешние шрифты, карты и скрипты сторонних доменов. Единственное, что хранится в браузере, — выбранные размер шрифта и цветовая схема (`localStorage`, ключ `gym4-a11y`).
- Не является системой управления содержимым: правка выполняется в HTML-файлах. План перехода на CMS — в ADMIN_GUIDE.
