# Руководство администратора

## 1. Как устроен сайт

Каждая страница — самостоятельный HTML-файл с общей рамкой: демонстрационная полоса, утилитарная строка с телефоном и быстрыми ссылками, шапка, меню, панель доступности, содержимое и подвал. Внутренние страницы дополнительно используют боковую навигацию, карточки, документные списки, таблицы и FAQ. Рамка повторяется в HTML, потому что у сайта нет сборщика. **При изменении меню или подвала правьте все `*.html` одинаково**.

Стили — в `assets/css/style.css`. Скрипт `assets/js/app.js` отвечает за мобильное меню, панель доступности, подсветку текущего раздела, а также поиск, фильтрацию и сортировку новостей.

## 2. Как вносить данные

Заглушка выглядит так:

```html
<span class="ph">[внести данные]</span>
```

Замените весь `<span>` на реальный текст. Для карточки раздела:

```html
<article class="block"><h3>Заголовок</h3><p>Описание</p>
<p class="ph-status">Раздел не заполнен. Ответственный и дата актуализации: <span class="ph">[указать]</span></p></article>
```

Замените описание на содержание, а строку `ph-status` — на «Актуально на ДД.ММ.ГГГГ». Таблицы: копируйте строку `<tr>…</tr>`, чтобы добавить запись.

Документы кладите в каталог `files/` (создайте его) и ссылайтесь так: `<a href="files/ustav-2026.pdf">Устав (PDF, 1,2 МБ)</a>`. Указывайте формат и размер, давайте файлам понятные латинские имена. Тексты ссылок должны быть содержательными, а не «скачать».

Изображения: каталог `assets/img/`, у каждого `<img>` обязателен атрибут `alt` (пустой `alt=""` — только для декоративных). Загружайте только согласованные к публикации фото; не публикуйте персональные данные обучающихся без законных оснований.

Чтобы добавить страницу: скопируйте внутреннюю страницу, измените `<title>`, `<h1>`, содержимое, якоря боковой навигации и `aria-current="page"`; добавьте ссылку в основное меню и подвал всех страниц; запустите `tools/check_site.py` и `node --check assets/js/app.js`.

## 3. Развёртывание на собственном сервере

Достаточно любого веб-сервера, раздающего статические файлы. Скопируйте в каталог сайта `*.html`, `assets/`, `robots.txt` (и `files/`, если есть).

Пример Nginx:

```nginx
server {
    listen 443 ssl http2;
    server_name example-school.ru;           # заменить на реальный домен
    root /var/www/gym4;
    index index.html;
    error_page 404 /404.html;

    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "DENY" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Content-Security-Policy "default-src 'self'; img-src 'self' data:; frame-ancestors 'none'" always;

    location /assets/ { expires 7d; }
    location ~ /\. { deny all; }             # скрытые файлы
}
server { listen 80; server_name example-school.ru; return 301 https://$host$request_uri; }
```

Для Apache эквивалент — `Header set …` в `.htaccess` и `ErrorDocument 404 /404.html`. Сертификат (например, Let's Encrypt) настраивается на уровне сервера. Политика CSP выше допустима, потому что на сайте нет внешних ресурсов и встроенных скриптов; при добавлении карты или видео её нужно расширить.

## 4. Резервное копирование и обновление

Единственный источник — репозиторий Git; рабочая копия на сервере — результат копирования. Резервная копия: сам репозиторий и каталог `files/` (документы). Порядок обновления: правка → `python3 tools/check_site.py` → коммит → копирование на сервер (`rsync -av --delete --exclude docs --exclude tools --exclude .git ./ /var/www/gym4/`).

## 5. Безопасность

- Сайт статический: нет базы данных, серверного кода и учётных записей, поэтому поверхность атаки минимальна. Основные риски — доступ к серверу и репозиторию: включите двухфакторную аутентификацию, выдавайте права минимально необходимым людям.
- Внешних скриптов, шрифтов и счётчиков нет: данные посетителей третьим лицам не передаются.
- Форма обратной связи не добавлялась намеренно. Её можно добавить только после решения школы о целях и правовом основании обработки персональных данных, сроках хранения, ответственном и безопасном серверном приёме (CSRF, ограничение частоты, антиспам). Не используйте внешние конструкторы форм без оценки передачи данных.
- Если подключаются метрики, баннер об использовании cookie и уведомление об обработке данных должны быть согласованы и добавлены отдельно.

## 6. Доступность

Есть ссылка «Перейти к основному содержанию», осмысленные заголовки, `aria-current`, видимый фокус, управление с клавиатуры (Tab, Esc закрывает меню и панель), таблицы с `caption` и `scope`, контраст не ниже 4,5:1 в обычной схеме, панель «Версия для слабовидящих» (размер шрифта 100–200 % и две контрастные схемы), печатная версия. Перед запуском проверьте страницы со скринридером и при необходимости сверьте с требованиями ГОСТ Р 52872 и действующими нормативами к официальным сайтам.

## 7. Перспектива: редактирование без HTML

Если сотрудникам нужен браузерный редактор, варианты по возрастанию сложности: статический генератор с редактором Markdown (Hugo, Eleventy) и Git-интерфейсом; готовая CMS на сервере школы (WordPress, Wagtail, Django + Django Admin) с PostgreSQL, Nginx/HTTPS, ролями «администратор / главный редактор / редактор» и резервным копированием БД и media. Структура страниц и список разделов из этого проекта переносятся в шаблоны CMS без изменений. Сохраните адреса `/sveden/…` и настройте 301-перенаправления со старого сайта.


## Фотографии, социальные ссылки и доступность

Фотоблоки находятся на главной странице и в новостях. Замените помеченные заглушки на фотографии, согласованные администрацией. Для каждого снимка добавьте осмысленный alt-текст, дату и подпись; не публикуйте изображения детей без необходимых согласий. В блоке подвала замените неактивную карточку сообщества на точную ссылку, предоставленную администрацией.

Панель доступности управляет размером текста, контрастной схемой, межстрочным интервалом и видимостью изображений. Настройки сохраняются в localStorage браузера; «Сбросить» возвращает стандартные параметры.
