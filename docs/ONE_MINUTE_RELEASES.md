# Быстрые релизы Gym4: подготовка, передача и установка

Цель: подготовить один архив с исходниками релиза, передать его на VPS вместе с SHA-256 checksum и установить одной командой. Это дополняет, а не заменяет первоначальную установку из `docs/ELECTIONS_VPS_DEPLOYMENT.md`.

## 1. Что нужно сделать перед выпуском

1. Изменения должны быть закоммичены в Git.
2. Рабочее дерево должно быть чистым: пакетировщик специально откажется собирать архив из незакоммиченных файлов.
3. Проверьте CI и PR. Не собирайте официальный релиз из случайной feature-ветки: сначала должна быть утверждена именно та версия, которую собираетесь публиковать.
4. Убедитесь, что на VPS уже выполнена первоначальная установка, настроен HTTPS и проверено резервное копирование.

## 2. Собрать комплект на своём компьютере

Из корня репозитория:

```bash
bash deploy/package-release.sh
```

Скрипт создаст в `releases/` два файла:

- `gym4-release-<дата>-<commit>.tar.gz` — исходники конкретного коммита;
- `gym4-release-<дата>-<commit>.tar.gz.sha256` — контрольная сумма.

Архив создаётся через `git archive`: в него не попадут локальные незакоммиченные файлы, `.git`, локальные секреты, VPS database/media и рабочая директория. Перед сборкой скрипт проверяет чистоту Git. Каталог `releases/` не должен попадать в Git.

## 3. Передать на VPS

Передайте оба файла (архив и checksum) администратору сервера через согласованный защищённый канал. Не отправляйте `deploy/.env`, пароли, дампы БД или пользовательские загрузки вместе с релизом.

Пример загрузки с локальной машины:

```bash
scp releases/gym4-release-*.tar.gz* admin@SERVER:/tmp/
```

Если в `releases/` несколько комплектов, укажите точное имя одного архива и соответствующего ему checksum-файла.

## 4. Установить релиз одной командой

На VPS:

```bash
sudo bash /path/to/gym4-site/deploy/apply-release.sh /tmp/gym4-release-YYYYMMDD-HHMMSS-COMMIT.tar.gz
```

Скрипт:

1. Проверяет SHA-256 и безопасные пути внутри архива.
2. Проверяет, что комплект содержит обязательные файлы приложения.
3. Создаёт резервную копию БД, media и `.env` штатным backup-скриптом.
4. Сохраняет архив предыдущих файлов приложения.
5. Обновляет исходники, сохраняя `.git`, `deploy/.env`, `var/` и runtime-каталог `public/`.
6. Пересобирает публичную часть сайта, проверяет Compose-конфигурацию и пересобирает контейнер.
7. Проверяет Django system checks, состояние миграций, HTTP сайта и страницу входа.
8. При ошибке до успешного health check возвращает предыдущие файлы и пересобирает предыдущую версию контейнера.

Скрипту нужен установленный `rsync`; на Debian/Ubuntu: `sudo apt-get install -y rsync`.

## 5. Откат и ограничения

Архив исходников и резервные копии сохраняются в `/var/backups/gym4-site/`. Скрипт автоматически откатывает файлы приложения при ошибке. Резервная копия БД сохраняется отдельно: автоматический откат схемы базы намеренно не выполняется, поскольку обратное применение миграций может повредить данные. Если релиз успел применить несовместимую миграцию, остановите публикацию и восстановите БД из соответствующего дампа по отдельной проверенной процедуре.

Для production-миграций используйте расширяемый/совместимый подход: сначала добавление новых полей и таблиц, затем перевод приложения, удаление старых полей — отдельным релизом после проверки. Не совмещайте необратимые миграции и выкладку критичных данных в один шаг.

После успешного деплоя проверьте:
- главную страницу и несколько внутренних URL;
- `/portal/login/` и вход тестового пользователя;
- загрузку CSS/JS и изображений;
- публикацию/модерацию в тестовой кампании;
- логи контейнера и свободное место;
- что HTTPS продолжает работать.

## 6. Что не делает этот механизм

- Не выполняет первоначальную установку VPS и не настраивает DNS/HTTPS.
- Не отправляет архив на сервер автоматически: передача файлов остаётся отдельным шагом.
- Не меняет `.env` и не переносит секреты между серверами.
- Не заменяет согласование релиза, CI, резервное копирование и проверку человеком.
- Не гарантирует «одну минуту» при медленном VPS или пересборке Docker-образа. Цель — свести ручные действия к передаче двух файлов и одной команде.
