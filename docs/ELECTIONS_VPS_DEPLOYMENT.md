# Развёртывание серверного модуля выборов

## Что входит

Серверный модуль находится в каталоге server/ и не заменяет статическую демоверсию на GitHub Pages.

- Django 5.2, Gunicorn и PostgreSQL 16.
- Docker Compose для приложения и базы данных.
- Nginx на VPS: статические страницы из каталога public/, проксирование /portal/, /admin/, /api/, /media/ и /static/.
- Кабинет кандидата: собственные карточки, новости и агитационные материалы.
- Очередь модерации: организатор или модератор одобряет публикацию либо возвращает её с комментарием.
- Django Admin: создание учётных записей, назначение ролей и привязка пользователя к карточке кандидата.
- Аудит действий с материалами.

**Электронное голосование не реализовано.** API публикаций не принимает бюллетени и не считает голоса. Статическая демоверсия голосования остаётся отдельным локальным макетом.

## Требования к VPS

- Debian 12+ или Ubuntu 22.04+.
- 1–2 GB RAM (для маленькой кампании; 2 GB предпочтительнее), 1 vCPU, свободное место под базу и медиа.
- Docker Engine с Compose v2, Nginx, открытые порты 80/443.
- Домен, A/AAAA-запись которого указывает на VPS.
- Репозиторий клонирован на сервер.

Установка рассчитана на один небольшой школьный проект. База PostgreSQL не публикуется наружу; приложение слушает только 127.0.0.1:8000.

## Установка

Сначала клонируйте репозиторий и перейдите в него:

~~~bash
git clone https://github.com/AL3XZIG/gym4-site-test.git
cd gym4-site-test
sudo bash deploy/install.sh elections.example.org
~~~

Замените elections.example.org на домен, направленный на VPS. Скрипт:

1. Проверит/установит Nginx, Docker Engine и Compose v2 из пакетов Debian/Ubuntu.
2. Создаст секреты в deploy/.env с правами 0600 (файл исключён из Git).
3. Соберёт публичную копию сайта в public/. В неё попадают только публичные HTML-страницы, assets/ и robots.txt; исходники сервера, .env, документация и локальные редакторы не публикуются через Nginx. Из production-копии удаляются demo-полосы, ссылки на локальные редакторы, их JS/CSS и тестовые карточки/бюллетень.
4. Добавит отдельный Nginx virtual host и ограничение частоты попыток входа. Существующий default site не удаляется.
5. Запустит PostgreSQL и Django, применит миграции и соберёт статику.
6. Предложит создать первого суперпользователя Django — главного организатора.

Установка не удаляет и не перезаписывает существующий чужой Nginx-конфиг. При повторном запуске собственный конфиг сохраняется в backup; если в нём уже настроен TLS через Certbot, установщик откажется его перезаписывать.

### HTTPS — обязательно до выдачи паролей

После того как DNS указывает на VPS и порт 80 доступен:

~~~bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx --redirect -d elections.example.org
~~~

Проверьте https://elections.example.org/portal/login/. Только после успешной проверки HTTPS выдавайте кандидатам логины и временные пароли. Не пересылайте пароли в общие чаты.

## Создание пользователей и ролей

Войдите в /admin/ под первым суперпользователем.

1. Создайте пользователя в разделе Users. Установите временный пароль и сообщите его участнику индивидуально.
2. В профиле пользователя назначьте роль candidate, moderator или organizer.
3. Для кандидата создайте запись в разделе Candidates: привяжите пользователя и задайте уникальный public_id (латиница, цифры и дефисы, например candidate-01).
4. Роль organizer автоматически включает ограниченный Staff status и права только на учётные записи, роли, карточки кандидатов и настройки кампании. Полные системные права остаются только у первого суперпользователя.
5. Модератор получает доступ к очереди, но не к управлению учётными записями. Кандидат входит в /portal/login/ и работает только со своими материалами.

Самостоятельной регистрации нет. Кандидат не может увидеть или изменить черновики другого участника, изменить роль, управлять пользователями или опубликовать материал без модерации.

## Редакционный процесс

1. Кандидат создаёт карточку профиля, новость или агитационный материал.
2. Материал сохраняется как черновик.
3. Кандидат нажимает «Отправить на проверку».
4. Организатор/модератор открывает /portal/moderation/.
5. Модератор либо публикует материал, либо возвращает его с комментарием.
6. Публичный API и страницы получают только записи со статусом published.

Новая версия уже опубликованной карточки создаётся как отдельная заявка; предыдущая опубликованная версия остаётся видимой до одобрения новой. Загруженные файлы хранятся в приватном каталоге и доступны посетителям только через проверку статуса публикации. Допускаются JPG, PNG, WebP и PDF до 8 МБ; SVG и HTML запрещены.

## Обновление через комплект релиза (рекомендуется)

Чтобы не скачивать изменения по одному файлу и не зависеть от Git-доступа сервера, соберите переносимый комплект на своём компьютере:

~~~bash
bash deploy/package-release.sh
~~~

Будут созданы архив `releases/gym4-release-....tar.gz` и файл контрольной суммы `.sha256`. Перед сборкой изменения должны быть закоммичены, а Git working tree — чистым.

Передайте на VPS оба файла по защищённому каналу. Затем на VPS выполните одну команду:

~~~bash
sudo bash /path/to/gym4-site/deploy/apply-release.sh /tmp/gym4-release-....tar.gz
~~~

Скрипт проверит checksum, создаст backup БД/media/.env и исходников, применит обновление, пересоберёт контейнер, проверит Django и HTTP. При ошибке до успешной проверки исходники будут возвращены к предыдущей версии. Подробности, требования к rsync и ограничения отката — в [руководстве по быстрым релизам](ONE_MINUTE_RELEASES.md).

Старый вариант прямого обновления из Git остаётся доступен:

~~~bash
sudo bash deploy/update.sh
~~~

Или передайте архив как аргумент:

~~~bash
sudo bash deploy/update.sh /tmp/gym4-release-....tar.gz
~~~

## Резервные копии

Ручной запуск:

~~~bash
sudo bash deploy/backup.sh
~~~

По умолчанию архивы сохраняются в /var/backups/gym4-site с правами только для root; в комплект входят deploy/.env, дамп БД и media, файлы старше 14 дней удаляются. Установщик включает ежедневный systemd timer. Это не заменяет off-site backup: периодически копируйте архивы на отдельное защищённое хранилище и проверяйте восстановление.

## Ограничения и защита данных

- Не используйте модуль для настоящего электронного голосования. Сейчас нет списка избирателей, одноразовых допусков, тайны бюллетеня, защиты от повторного голосования и проверяемого подсчёта.
- Не собирайте даты рождения, адреса, личные телефоны, пароли от сторонних сервисов и другие лишние сведения.
- Публикация имён, фотографий, класса и материалов несовершеннолетних должна быть согласована администрацией и иметь надлежащее правовое основание/согласия.
- Кандидатские материалы всегда проходят предварительную модерацию. Не публикуйте оскорбления, травлю, угрозы, персональные данные и неподтверждённые обвинения.
- До запуска школа должна определить оператора данных, цели и сроки хранения, круг сотрудников с доступом и процедуру удаления/выгрузки.
- Включите HTTPS, обновления ОС/Docker, мониторинг свободного места и проверку восстановления backup.
- Установщик не меняет firewall и не удаляет default Nginx site. Настройте firewall отдельно, оставив наружу только SSH, HTTP и HTTPS.
