# Реестр архитектурных и продуктовых решений

## 1. Два независимых контура

### Демонстрация
- Статические HTML/CSS/JS-файлы.
- Публикация через GitHub Pages.
- Нет базы данных, серверной авторизации, API и формы отправки.
- Все страницы должны оставаться читаемыми без JavaScript.
- Содержимое обновляется прямым редактированием HTML.

### Production
- Отдельное серверное приложение, если администрация школы одобрит такой переход.
- Роли редакторов, журналирование, резервное копирование, управление документами и серверная обработка обращений.
- В `docs/PRODUCTION_ARCHITECTURE.md` зафиксирован предварительный вариант Django + PostgreSQL + Nginx. Это предложение, не готовая реализация.

## 2. Объединение старых прототипов

Исторические HTML-копии, Python-генераторы и промежуточные снимки разобраны; полезная архитектурная заметка сохранена в `docs/PRODUCTION_ARCHITECTURE.md`. Текущая сборка не зависит от генераторов.

В актуальный статический проект перенесены:
- крупная главная композиция и типографическая иерархия;
- быстрые ссылки на основные задачи посетителя;
- отдельные страницы для родителей, обучающихся, новостей, приёма и сведений;
- общая дизайн-система;
- мобильная навигация и настройки доступности;
- концепция разделения демо и production CMS.

Не перенесены без дополнительного обоснования:
- неподтверждённые статистические показатели и старые новости;
- фиктивная отправка формы;
- cookie-баннер без соответствующей функциональности;
- внешние шрифты и декоративные анимации;
- эмодзи как навигационные иконки.

## 3. Дизайн-система

- Основные цвета: глубокий синий, белый, светло-серый и сдержанный золотистый акцент.
- Типографика — системные шрифты без сетевых запросов.
- Сетка — CSS Grid и Flexbox; мобильная версия не является уменьшенной копией desktop.
- Контраст, видимый фокус, семантические заголовки и доступность с клавиатуры — обязательны.
- Не использовать декоративные эффекты, которые отвлекают от информации.
- Фотографии использовать только после получения и проверки официальных материалов школы.

## 4. Контент и достоверность

- Стабильные исторические факты можно использовать только со ссылкой на официальный источник и отметкой даты проверки.
- Динамические данные (контакты, ФИО, расписания, новости, меню, вакантные места, документы) должны подтверждаться ответственным сотрудником.
- У каждой публикации должны быть дата, заголовок, текст, ответственный редактор и срок актуальности.
- Не публиковать персональные данные обучающихся без надлежащего правового основания.
- Не оставлять фиктивные формы и кнопки, имитирующие работу серверных сервисов.

## 5. Проверка контента

- Статусы контентного чек-листа сохраняются только в браузере редактора.
- Отметка «Подтверждено» означает локальную отметку проверяющего, а не официальное согласование школы.
- Отчёт нужно приложить к первоисточникам и согласованию ответственных сотрудников.

## 6. GitHub Pages

- Точка входа — `index.html` в корне.
- В публикацию попадают только корневые HTML-файлы, `assets/`, `robots.txt` и `.nojekyll`.
- `docs/` и `tools/` остаются в репозитории, но не попадают в публичную сборку. В workflow перечислены только рабочие HTML-страницы; новые файлы в корне нельзя публиковать случайно.
- Source в Settings → Pages должен быть установлен в GitHub Actions.
