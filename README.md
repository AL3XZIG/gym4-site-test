# Сайт Гимназии № 4

Многостраничный статический сайт образовательной организации. Основной стек — HTML5, CSS и небольшой vanilla JavaScript. Для отображения и локального редактирования не нужны Python, Node.js, npm, база данных или сборщик.

> **Статус:** первая предрелизная демонстрация 0.1.0-rc.1. Это не production и не официальный источник сведений. Перед официальным запуском администрация должна подтвердить тексты, контакты, документы, даты, ссылки и изображения. Визуальные редакторы и чек-лист работают локально в браузере.

## Первая предрелизная версия 0.1.0-rc.1

Состав и ограничения этой версии описаны в [чек-листе предрелиза](docs/PRE_RELEASE_0.1.0-rc.1.md). В этой итерации:
- упрощена мобильная шапка и увеличены интерактивные зоны;
- удалены внешние запросы Google Fonts, используется системная типографика;
- усилена обработка отказа Canvas-анимации логотипа с возвратом к статичной «4»;
- редактор новостей проверяет даты и URL, а карточки без источника больше не ведут на несуществующий якорь;
- визуальный редактор очищает экспорт от временных интерфейсных элементов и проверяет URL перед применением;
- проверка репозитория расширена на доступность ссылок, безопасность URL, JSON и локальные ресурсы.

## Структура проекта

- `index.html` — главная страница.
- `sveden.html` — сведения об образовательной организации.
- `parents.html` — информация для родителей.
- `students.html` — информация для обучающихся.
- `news.html` — новости и объявления.
- `priem.html` — приём в гимназию.
- `contacts.html` — контакты и порядок обращений.
- `404.html` — страница ошибки.
- `assets/css/style.css` — общая дизайн-система и адаптивная вёрстка.
- `assets/js/app.js` — общий интерфейс, поиск, доступность, сезонные эффекты и анимированный логотип.
- `assets/js/content-review.js` — локальный чек-лист готовности контента в демо-админке.
- `assets/js/news.js`, `news-editor.js`, `school-life.js`, `election.js` — новости, редактор, школьная жизнь и демонстрация выборов.
- `assets/data/election.json` — демонстрационные профили кандидатов и настройки тестового голосования.
- `assets/img/` — favicon и согласованные изображения.
- `tools/check_site.py` — автоматическая проверка локальных ссылок, якорей и структуры.
- `docs/` — руководство администратора, чек-лист и решения проекта.
- `.github/workflows/pages.yml` — проверка и публикация на GitHub Pages.
- `docs/TEMPLATE_AUDIT.md` — результаты разбора и объединения шаблонов.
- `docs/PRODUCTION_ARCHITECTURE.md` — предложение по будущей серверной CMS, не реализованный backend.

## Принятые архитектурные решения

1. **Демо — статический сайт.** Каждая страница редактируется как HTML-файл. Генератор не используется: страницы редактируются напрямую в HTML, стили — в общем CSS, поведение — в JS.
2. **Единая дизайн-система и контентные паттерны.** Внутренние разделы используют боковую навигацию, карточки, документные списки, таблицы, FAQ и пошаговые инструкции. Общая шапка, навигация и подвал повторяются в HTML, поэтому изменения нужно синхронно вносить во все страницы.
3. **Никаких фиктивных функций.** Форма обратной связи не имитирует отправку данных. GitHub Pages не хранит данные и не предоставляет редактор.
4. **Факты требуют источника.** Часть сведений перенесена с gym4.net (срез от 15.11.2026; происхождение и ограничения отражены в `docs/GYM4_DATA.md`). Это вторичный перенос, а не подтверждение администрацией. Адреса электронной почты на исходном сайте расходятся; условия приёма 2026–2027 и вакантные места помечены как архивные. Контакты, документы, расписания и кадровые сведения требуют подтверждения.
5. **Production — отдельный этап.** Если школе потребуется редактирование через браузер, роли сотрудников, публикация новостей и загрузка документов, нужна серверная CMS. Предложение по Django и PostgreSQL сохранено в `docs/PRODUCTION_ARCHITECTURE.md` как архитектурный вариант, а не как реализованная функция.

## Локальный просмотр и проверка

Откройте `index.html` в браузере или запустите локальный HTTP-сервер:

```bash
python3 -m http.server 8000
```

Затем откройте `http://localhost:8000`.

Проверки перед коммитом:

```bash
python3 tools/check_site.py
node --check assets/js/app.js
```

Python используется только для проверочного скрипта. Сам сайт работает без него.

## GitHub Pages

1. Откройте **Settings → Pages**.
2. В поле **Build and deployment → Source** выберите **GitHub Actions**.
3. Выполните push в `main`.
4. Workflow проверит сайт и опубликует только явно перечисленные рабочие страницы, `assets/`, `robots.txt` и `.nojekyll`. Документация и инструменты в публичную сборку не попадут.

Если Pages уже настроен на публикацию из ветки, переключите Source на GitHub Actions.

## Передача администратору школы

1. Передайте репозиторий и документы из `docs/`.
2. Назначьте ответственных за каждый раздел.
3. Найдите незаполненные поля: `grep -rn 'class="ph"' --include='*.html' .`.
4. Подтвердите каждый факт по официальному документу или ответственному сотруднику.
5. Согласуйте фотографии и подписи к ним; не публикуйте персональные данные несовершеннолетних без законного основания.
6. Проверьте сайт на телефоне, десктопе, клавиатурой и со скринридером.
7. Перед production-публикацией уберите демонстрационную полосу и все внутренние подсказки.

## Выборы президента гимназии

Раздел `election.html` показывает карточки кандидатов, программы и материалы кампании. Данные редактируются в `assets/data/election.json`; структура и ограничения описаны в [руководстве по демонстрации выборов](docs/ELECTIONS_DEMO.md). Голосование в GitHub Pages только локальное демонстрационное: выбранный ID хранится в `localStorage`, не отправляется на сервер и не считается реальным голосом. Для настоящих выборов необходим отдельный backend и утверждённый школой регламент.

## Ограничения

- Нет базы данных, серверной авторизации, общей CMS или серверного API. `admin.html` — только локальный демонстрационный редактор и чек-лист.
- Нет отправки форм и хранения обращений.
- Новости и объявления редактируются через локальный редактор и экспорт `news.json`; сохранение и публикация всё равно требуют замены файла в репозитории.
- Структура раздела «Сведения» должна быть отдельно сверена с действующими требованиями к официальным сайтам образовательных организаций.
- Текущая версия предназначена для демонстрации дизайна и архитектуры, а не для автоматического переноса на официальный домен.
