# QA и критерии приёмки v4

## 1. Автоматические проверки

### Backend
- unit tests моделей, permissions и сервисов;
- integration tests для публикации, архивирования и медиа;
- API tests: анонимный доступ, роль editor, reviewer и chief editor;
- миграции: чистая БД → latest; upgrade с предыдущей схемы;
- security checks: CSRF, upload validation, escaping, rate limiting.

### Frontend
- HTML validation и проверка доступности;
- lint/format для JS и CSS;
- проверка всех внутренних ссылок и маршрутов;
- отсутствие console errors;
- отсутствие mixed content и внешних ресурсов без согласования.

### E2E (Playwright)
1. Главная открывается и навигация работает.
2. Мобильное меню открывается/закрывается клавиатурой и касанием.
3. Поиск возвращает только опубликованные материалы.
4. Редактор создаёт черновик и видит предпросмотр.
5. Анонимный пользователь не может открыть редакторские действия.
6. Editor не может публиковать, если его роль этого не разрешает.
7. Reviewer согласует/отклоняет материал.
8. Публикация отражается на публичной странице.
9. Неодобренный файл недоступен по прямому URL.
10. Архивная запись не появляется в публичной выдаче.

## 2. Матрица ручной проверки

| Область | Проверка | Критерий |
|---|---|---|
| Mobile | 320, 360, 390, 768 px | нет горизонтального overflow, элементы доступны |
| Desktop | 1280, 1440, 1920 px | сетка и типографика стабильны |
| Zoom | 200% | контент не обрезан, действия доступны |
| Keyboard | Tab, Shift+Tab, Enter, Space, Escape | логичный порядок и видимый фокус |
| Screen reader | landmarks, headings, labels, errors | понятная структура и названия |
| Motion | prefers-reduced-motion | анимации отключаются/упрощаются |
| Contrast | текст, кнопки, состояния | соответствует WCAG 2.2 AA по возможности |
| Forms | пустые/длинные/невалидные значения | ошибки понятные, данные не теряются |
| Browser | Chromium, Firefox, WebKit | ключевые сценарии одинаковы |

## 3. Security acceptance

- DEBUG=False и корректные ALLOWED_HOSTS.
- Секреты отсутствуют в Git, build artifacts и логах.
- База данных не доступна извне.
- HTTPS и secure cookies включены.
- CSRF защита включена для изменяющих запросов.
- Пользователь без роли не может менять данные через API напрямую.
- Проверяются ownership и object-level permissions.
- Загрузка отклоняет неподдерживаемый MIME, чрезмерный размер и опасные имена.
- Публичная выдача не раскрывает draft, email редакторов и внутренние заметки.
- Rate limiting включён для login и публичных форм.
- Заголовки безопасности и CSP проверены на реальном deployment.

## 4. Deployment acceptance

- чистая установка на поддерживаемый Debian/Ubuntu;
- повторный запуск installer идемпотентен;
- обновление не перезаписывает чужой Nginx config;
- health check подтверждает готовность web и database;
- backup включает PostgreSQL и media;
- restore проверен на отдельном чистом окружении;
- есть инструкция rollback;
- сервер переживает reboot и корректно поднимает сервисы.

## 5. Release gate

v4 не публикуется, если остаётся хотя бы один блокирующий дефект:
- утечка черновика/секрета/персональных данных;
- обход прав редакторских ролей;
- потеря контента при обновлении или восстановлении;
- битый обязательный маршрут/документ;
- критическая ошибка мобильной навигации;
- неподтверждённые официальные сведения;
- отсутствие HTTPS или проверенного backup restore.

## 6. Что не считать доказательством готовности

- успешный запуск локально;
- зелёный unit test без E2E;
- наличие кнопки без работающего backend;
- backup без проверенного restore;
- красивый макет без тестирования на телефоне;
- заполненный раздел без подтверждения владельцем информации.
