# План разработки v4

Порядок выбран так, чтобы сначала определить контракты и границы системы, затем собрать функциональные блоки, а не делать ещё один несвязанный редизайн.

## Этап 0. Подготовка — начат

- [x] Создать изолированную рабочую область `release/`.
- [x] Зафиксировать текущую v0.3 как контрольную демоверсию.
- [x] Описать целевую архитектуру, модель данных и тестовую стратегию.
- [ ] Провести инвентаризацию всех HTML-страниц, JS-модулей, JSON-данных и Django-приложения.
- [ ] Составить карту URL v0.3 → v4.
- [ ] Зафиксировать список функций, которые сохраняются, объединяются или удаляются.

**Результат:** спецификация v4 и перечень повторно используемого кода.

## Этап 1. Каркас приложения

- [ ] Подготовить Django project для полного сайта, не ломая текущий модуль выборов.
- [ ] Разнести настройки development/test/production.
- [ ] Подключить PostgreSQL, миграции, health endpoint и структурированное логирование.
- [ ] Ввести базовый layout, шаблоны страниц, общую навигацию, подвал и дизайн-токены.
- [ ] Настроить локальный запуск одной командой и CI для backend/frontend.
- [ ] Ввести проверку конфигурации и безопасные значения по умолчанию.

**Результат:** пустой, но разворачиваемый v4-каркас с тестами.

## Этап 2. CMS и редакционный процесс

- [ ] SiteSettings: реквизиты, контакты, логотип, соцсети, расписание приёма.
- [ ] Pages: страницы, блоки, slug, SEO, черновик/публикация/архив.
- [ ] News: новости, категории, обложки, дата публикации, отложенная публикация.
- [ ] Documents: файлы, тип, дата, версия, доступность, архивирование.
- [ ] Menus: управляемая навигация с безопасными URL.
- [ ] Media library: загрузка, проверка MIME/размера, alt-текст, права.
- [ ] Preview и workflow: автор → редактор → главный редактор → публикация.
- [ ] История изменений и аудит действий.
- [ ] Разграничение прав на уровне объектов и операций.

**Результат:** сотрудники могут безопасно обновлять содержание через браузер, без Git и HTML.

## Этап 3. Публичный сайт

- [ ] Перенести главную и общую рамку.
- [ ] Перенести разделы «Сведения», «Родителям», «Обучающимся», «Приём», «Контакты».
- [ ] Перенести новости, школьную жизнь, достижения, документы и календарь.
- [ ] Реализовать поиск по опубликованному содержимому.
- [ ] Реализовать сезонные эффекты и праздничный логотип как необязательный декоративный слой.
- [ ] Сохранить reduced motion, клавиатурную навигацию и доступность.
- [ ] Не переносить демо-голосование как реальное; модуль выборов остаётся отдельным контуром.

**Результат:** все разделы работают на данных CMS, а не на разрозненных HTML/JSON-файлах.

## Этап 4. Модуль выборов

- [ ] Интегрировать существующий `server/` после аудита моделей, прав и API.
- [ ] Убрать дублирующиеся сущности между CMS и приложением выборов.
- [ ] Сохранить модерацию кандидатских материалов и журнал действий.
- [ ] Оставить электронное голосование выключенным, пока нет отдельного утверждённого проекта, регламента и независимого аудита.

**Результат:** согласованный модуль кампании без ложного обещания безопасного электронного бюллетеня.

## Этап 5. Production и эксплуатация

- [ ] Docker Compose для web + PostgreSQL; reverse proxy и HTTPS.
- [ ] Постоянные volumes для БД и media.
- [ ] Секреты только через окружение/secret store.
- [ ] Резервное копирование БД и media, ротация и проверяемое восстановление.
- [ ] Обновление с preflight-проверкой и автоматическим rollback там, где он безопасен.
- [ ] Health checks, логи, мониторинг диска и места для резервных копий.
- [ ] Инструкция развёртывания на чистом Debian/Ubuntu VPS.

**Результат:** воспроизводимое развёртывание и понятная процедура восстановления.

## Этап 6. Проверка и сборка релиза

- [ ] Unit + integration + API tests.
- [ ] Playwright E2E для публичных страниц и редакторских сценариев.
- [ ] Проверка мобильных размеров, браузеров, клавиатуры, контраста и zoom 200%.
- [ ] Проверка безопасности: права, CSRF, XSS, upload validation, rate limiting, headers, секреты.
- [ ] Проверка миграции данных и всех старых URL.
- [ ] Проверка backup → restore на отдельном окружении.
- [ ] Сборка публичного артефакта и проверка состава файлов.
- [ ] Выпуск RC, приёмка, исправления, затем v4.0.0.

**Результат:** воспроизводимый release artifact и документированный чек-лист приёмки.

## Правило завершения этапа

Этап не считается готовым только потому, что страница открывается. Для каждого пункта нужны: реализация, тест, проверка негативного сценария, документация и отметка в `STATUS.md`.
