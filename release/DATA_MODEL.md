# Модель данных CMS v4

Модель намеренно небольшая: сначала закрыть редакционные сценарии гимназии, затем расширять её по реальным требованиям.

## Общие правила

- Все записи имеют primary key, `created_at`, `updated_at` и автора изменения.
- Публичная выдача фильтруется по статусу `published` и времени публикации.
- Slug уникален в пределах типа контента.
- Даты хранятся в timezone-aware формате; интерфейс отображает локальное время.
- HTML из редактора не считается доверенным: разрешённый набор тегов/атрибутов проходит sanitization.
- Удаление опубликованных документов и страниц по умолчанию заменяется архивированием.
- Персональные данные не собираются без отдельного согласованного процесса.

## Сущности

### SiteSettings
Название организации, официальное наименование, адрес, телефоны, email, часы работы, ссылки, логотип, SEO defaults. Изменения реквизитов логируются.

### Page
- `title`, `slug`, `summary`, `body` или структурированные блоки;
- `status`: draft / review / published / archived;
- `published_at`, `author`, `reviewer`;
- SEO title/description;
- `show_in_menu`, `menu_order`.

Для критически важных сведений (например, обязательные документы) предусмотреть дату последней проверки и ответственного.

### NewsItem
- `title`, `slug`, `summary`, `body`;
- `category`, `cover_image`, `alt_text`;
- `status`, `published_at`, `author`, `reviewer`;
- источники/внутренние редакторские заметки отдельно от публичного тела.

### Document
- `title`, `category`, `file`, `mime_type`, `size`;
- `document_date`, `version`, `is_current`;
- `status`, `published_at`, `reviewed_at`, `reviewed_by`;
- доступное имя файла и понятный публичный URL.

### MenuItem
- `label`, `url`, `parent`, `position`, `is_active`;
- URL разрешён только для внутренних маршрутов или валидных HTTPS-ссылок;
- циклическая вложенность запрещена.

### MediaAsset
- файл, фактический MIME, размер, ширина/высота, checksum;
- alt text, подпись, автор/источник и статус разрешения на публикацию;
- private by default до проверки и публикации.

### AuditEvent
- actor, action, object type/id, timestamp, request correlation id;
- не записывать пароли, токены и избыточные персональные данные;
- журнал нельзя редактировать через обычный редакторский интерфейс.

## Роли

| Роль | Возможности |
|---|---|
| System admin | настройки системы, пользователи, deployment |
| Chief editor | просмотр/публикация/архивирование, назначение редакторов |
| Editor | создание и изменение черновиков, загрузка материалов |
| Reviewer | согласование назначенных материалов |
| Public | только чтение опубликованного |

Роль не должна давать доступ ко всем объектам автоматически: проверять разрешения на уровне каждой операции и объекта.

## Workflow публикации

1. Редактор создаёт draft.
2. Материал отправляется на review.
3. Проверяющий подтверждает содержание, источники, права на медиа и alt text.
4. Главный редактор публикует либо возвращает на доработку.
5. Система сохраняет событие аудита и версию.
6. Архивирование не уничтожает историю.

## Загрузка файлов

- allowlist типов, проверка расширения и фактического MIME;
- лимиты размера и количества;
- случайное серверное имя, исходное имя хранить как метаданные;
- файлы не исполняются и не хранятся в каталоге с исполняемыми правами;
- SVG, HTML и архивы не принимать в первой итерации без отдельной обработки;
- приватные/неодобренные файлы не должны быть доступны по прямому URL.

## Не входит в базовую CMS

- обработка обращений и формы с персональными данными;
- хранение данных учащихся;
- электронное голосование;
- массовые рассылки;
- платежи и сторонняя аналитика.

Для этих функций нужны отдельное обоснование, согласование и модель угроз.
