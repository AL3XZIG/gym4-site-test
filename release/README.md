# Gymnasium No. 4 — Release v4 workspace

**Статус:** подготовка v4, отдельный рабочий контур.  
**Базовая версия:** текущая демонстрационная ветка `main` (0.3.0-rc.1).  
**Назначение:** собрать следующую архитектуру и интерфейс, не ломая работающую демоверсию.

> Каталог `release/` — рабочая зона разработки, а не готовая публичная сборка. Ничего из него не публикуется GitHub Pages, пока отдельный build-процесс явно не будет настроен и проверен.

## Принцип работы

1. Текущие HTML-страницы, CSS/JS, редакторы и демонстрация выборов в корне остаются контрольным образцом v0.3.
2. Новые компоненты v4 разрабатываются внутри `release/`.
3. Каждый компонент должен иметь критерии готовности, тесты и описание интеграции.
4. Не копировать вслепую старые шаблоны и не переносить непроверенные сведения о гимназии.
5. После завершения функциональных блоков собирается единое приложение v4, проводится регрессия и только затем готовится переключение основной публикации.

## Содержание каталога

- `PLAN.md` — этапы и порядок реализации.
- `ARCHITECTURE.md` — целевая архитектура v4.
- `DATA_MODEL.md` — сущности и правила хранения контента.
- `QA.md` — тестовая стратегия и критерии приёмки.
- `STATUS.md` — текущий статус компонентов и известные ограничения.
- `DEMO_FINISH.md` — чек-лист завершения демо и идеи для презентации.
- `decisions/` — зафиксированные архитектурные решения.
- `frontend/` — новое приложение и компоненты интерфейса (будет наполняться).
- `backend/` — полная CMS и API (будет наполняться; существующий `server/` — исходник для повторного использования, не копия).
- `tests/` — тесты v4.
- `scripts/` — инструменты сборки, проверки и миграции.

## Как проверять

Пока каталог содержит проектную документацию, а не готовую сборку. Текущие проверки корневой демоверсии остаются прежними:

```bash
python3 tools/check_site.py
node --check assets/js/app.js
```

Проверки v4 будут добавляться рядом с реализацией и не должны подменять проверки старой версии.

## Условия перехода на v4

- весь публичный контент редактируется через авторизованную CMS;
- редакционные роли и workflow публикации проверены;
- статические маршруты и старые URL сохранены либо имеют согласованные redirects;
- адаптивность, доступность и безопасность проверены автоматическими и ручными тестами;
- сервер разворачивается с нуля по документации;
- резервная копия успешно восстановлена на чистом окружении;
- публичная сборка не содержит секретов, редакторских черновиков, тестовых данных и приватных файлов;
- школа подтвердила все факты, документы, контакты и права на изображения.
